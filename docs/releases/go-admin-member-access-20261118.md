# 관리자 추가 비밀번호 제거 — 후속 구현·검증

2026-11-18 한국시간. 기준: 직전 `baronado-meonggo-final-integrated-20261118.zip`의 전체 수정 소스. 이 문서가 관리자 접근 변경에 대해서는 직전 최종 보고서보다 최신이다.

## 결과

**추가 관리자 비밀번호를 입력하지 않는 구현과 격리 검증을 완료했다. 실제 관리자 계정 연결과 운영 배포는 아직 하지 않았다.**

멍멍GO에서 이미 로그인한 지정 관리자만 관리 화면과 관리 API를 이용한다. 일반 회원·비로그인은 차단한다. 현재 실제 사용자 중 누구에게 관리자 권한을 줄지 정해지지 않아 실제 계정 ID를 설정하지 않았다. ‘초코눈나’는 사용자가 테스트 계정이라고 했으므로 임의로 관리자에 지정하지 않았다.

운영 Supabase·GitHub main·운영 Vercel·실제 회원 권한·코인에는 변경이 없다. 이번 작업에는 새 DB 테이블이나 운영 SQL 적용이 필요하지 않다.

## 구현

- 기본 인증 방식은 `member`다. 서버 환경 변수의 고유 회원 UUID 목록 `ADMIN_MEMBER_IDS`와 기존 로그인 세션을 대조한다. 변경 가능한 닉네임·이메일이나 클라이언트 헤더로 권한을 부여하지 않는다.
- 서버에서 매 관리 요청마다 회원 활성 상태와 `session_version`을 다시 확인한다. 계정 정지·세션 버전 변경 시 기존 쿠키의 권한도 해제된다.
- 비동기 권한 검사로 바뀌는 모든 관리 경로와 공통 변경 요청 도우미에 `await`를 적용했다. Promise를 참으로 오인해 통과시키는 경로가 없는지 실제 요청으로 검사했다.
- 로그인한 관리자에게는 원래 관리 화면이 바로 열린다. 비로그인은 기존 멍멍GO 로그인으로 안내하고, 일반 회원은 권한 없음으로 표시한다. 이 방식에는 별도 관리자 비밀번호 입력란이 없다.
- 관리자 로그아웃은 멍멍GO 로그인 쿠키도 해제한다. 이전 관리자 비밀번호 쿠키나 공용 비밀번호는 member 방식에서 사용할 수 없다.
- 기존 공식 카드 관리자 헤더의 좁은 화면 여백이 본문보다 5px 커 가로로 넘치던 부분을 320px 여백과 일치시켰다. 설명 줄이 고정 높이를 넘지 않도록 헤더 높이도 내용에 맞췄다.
- 명단 누락·잘못된 ID·잘못된 인증 방식 설정은 접근 차단으로 처리한다. 개발/Preview 자동 통과도 member 방식에서는 동작하지 않는다.
- 기존 비밀번호 방식은 배포 전 복귀 호환용 `ADMIN_AUTH_MODE=password`에서만 남는다. 기본값은 member이고, 새 방식에서는 ADMIN_PASSWORD가 필요하지 않다. 운영 환경을 임의로 전환하지 않았다.

새 인증 7개 검증 묶음은 `verification/admin-member-result.json`에 있다.

1. 실제 멍멍GO 로그인으로 지정 UUID만 관리자 인식, 관리자 비밀번호와 Preview 자동 통과 없이 성공.
2. 27개 관리 경로·메서드에서 비로그인·일반 회원 차단.
3. 지정 관리자만 실제 관리용 강아지 데이터 조회.
4. 위조 회원 쿠키, 관리자 ID를 주장하는 헤더, 정상 형식의 과거 관리자 쿠키, 과거 공용 비밀번호로 접근 불가.
5. 관리 변경과 로그아웃에 외부 Origin 요청 거부 유지.
6. 관리자 계정 정지 및 세션 버전 변경으로 기존 로그인 권한 즉시 해제, 재로그인 후 정상 접근.
7. 관리자 로그아웃 시 공통 회원 쿠키 제거, 이후 비로그인 접근 불가.

실제 브라우저에서는 테스트 관리자 계정으로 공식 카드 5개 슬롯을 읽었고, 테스트 세트를 공개 중지한 뒤 재공개해 실제 저장 권한도 확인했다. 운영 카드에는 수행하지 않았다.

## 파일과 재현

- 최신 제품 코드: `source/`. 이번 변경만 보기: `CHANGED-FILES.json`.
- 새 검사: `source/tests/admin-member-access.test.mjs`, `qa/admin-member-checks.mjs`.
- `qa/run.mjs`는 기존 34개 검증 후 격리 서버만 member 방식으로 바꿔 신규 7개 검사를 실행한다. 테스트용 지정 UUID와 계정은 운영 관리자 설정이 아니다.
- 실제 실행 로그와 화면: `verification/`. 직전 통합 검증 결과는 `history/`에 포함했다.
- 기본 실행: `source/`에서 `node --test tests/*.test.mjs`, `npm run build`. lockfile과 의존성은 직전 성공한 설치 상태를 유지했다.
- 폰트는 앞선 지침대로 승인 원본을 내부에서만 복원했다. 새 ZIP에 폰트 바이너리·.env·서버 키·node_modules·빌드 산출물·DB 데이터는 넣지 않았다.

## 실제 계정 연결 전 필요한 정보

**관리자로 사용할 기존 멍멍GO 계정의 닉네임**이 필요하다. 닉네임은 사용자에게 계정을 확인하기 위한 정보이고, 최종 권한 설정에는 해당 계정의 고유 UUID를 사용한다. 실제 사용자 계정의 관리자 권한을 임의로 지정할 수 없어 이 정보만 남겨 두었다.

확정 후 서버 설정 후보는 `ADMIN_AUTH_MODE=member`, `ADMIN_MEMBER_IDS=<확인한 고유 회원 ID>`다. NEXT_PUBLIC_ 변수에 넣지 않는다. 기존 ADMIN_SESSION_SECRET과 Supabase 서버 설정은 유지한다. 기존 ADMIN_PASSWORD 값은 member 방식에서 사용하지 않는다. 이 설정은 아직 실제 운영에 적용하지 않았다.

## 남은 범위와 다음 단계

관리자 기능 자체의 추가 비밀번호 제거는 구현·검증 완료다. **실제 계정 연결은 대기 상태**이므로 운영 배포 승인을 완료했다고 말할 수 없다.

다음 담당자는 관리자 계정 닉네임을 받아 정확한 계정을 확인하고, UUID 설정 후보를 준비해야 한다. 그 뒤 별도 사용자 승인에 따라 검토/배포를 진행한다. 이번 답변이나 ‘다음 과정’이라는 지시는 운영 배포 승인으로 취급하지 않는다.

직전 보고서의 iPhone Safari 실제 소리 재생·카메라 권한/촬영·두 실제 휴대폰의 배틀 네트워크 전환, 운영 공식 사진 매핑은 여전히 미검증이다. 좁은 Chromium 화면이나 합성 이미지 API 검증과 구분한다. 초코눈나 1,000코인 지급은 다시 실행하지 않는다.

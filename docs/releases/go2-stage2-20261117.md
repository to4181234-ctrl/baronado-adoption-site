## 2026-11-17 중요 정정 — 공식 카드 시스템 이미 존재 (main 확인)

이전 기록의 "공식 카드 저장 모델 신규 설계 필요"라는 판단은 **철회**한다. `main`을 추가 조사해 다음 기존 구현을 확인했다.
- `app/api/go/official/route.js`: `go_official_sets`, `go_official_assets`, `go_official_owned`, `go_official_hidden`, `go_official_daily_draws` 조회와 공식 카드 발급/중복 선택/읽음 처리 RPC 연결.
- `components/GoOfficialAlbum.js`: 공식 도감, 구매 및 무료 뽑기, 숨겨진 카드 관련 UI의 기존 구현.
- `lib/goOfficial.js`: 공식 카드 전용 Storage `go-official-cards`, 전용 기능 플래그.
- 기존 카메라 `go_cards`와 공식 카드 소유 기록은 **코드상 분리되어 있다.** DB에 실제 테이블이 생성돼 있는지, 마이그레이션 적용 상태는 별도 검증 필요.

**최신 기획과 차이:** 기존 main은 공식 사진 슬롯 1~5 + 히든 슬롯 6 (5+1), 최신 Figma는 일반 슬롯 1~4 + 히든 5 (4+1). 기존 소스의 무료 뽑기·히든 지급 로직도 구 규칙이라 그대로 배포할 수 없다. 사용자 데이터 이전·기존 소유 기록의 슬롯 매핑을 결정하기 전에는 스키마/운영 데이터를 수정하지 않는다.

`lib/goStage2Collection.js`는 현재 DB와 무관한 미연결 보조 계산 코드로, 실제 공식 보유 시스템을 대체하거나 신규 데이터 모델이 필요한 증거가 아니다. 중복 구현하지 말고 기존 main 코드를 분기 작업에 필요한 범위만 선별적으로 통합/수정한다. 진행 전 기존 main의 SQL/RPC, 관리자, 공식 UI 전부 분석할 것.

- 운영 URL의 익명 `/api/go/official` 조회는 외부 검색 도구에서 접근 실패하여 실제 HTTP 응답 코드와 환경변수 플래그 상태는 확인되지 않음. 운영 기능 노출을 단정 금지.

## 코드에서 확인한 현재 데이터 경계
- 기존 `go_cards` 및 `go_card_index`는 촬영한 나만의 카드와 공개 게시물의 목록/삭제에 사용됨.

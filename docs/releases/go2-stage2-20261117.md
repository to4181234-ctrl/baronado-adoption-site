## 2026-11-17 중요 정정 — 공식 카드 시스템 이미 존재 (main 확인)

이전 기록의 "공식 카드 저장 모델 신규 설계 필요"라는 판단은 **철회**한다. `main`을 추가 조사해 다음 기존 구현을 확인했다.
- `app/api/go/official/route.js`: `go_official_sets`, `go_official_assets`, `go_official_owned`, `go_official_hidden`, `go_official_daily_draws` 조회와 공식 카드 발급/중복 선택/읽음 처리 RPC 연결.
- `components/GoOfficialAlbum.js`: 공식 도감, 구매 및 무료 뽑기, 숨겨진 카드 관련 UI의 기존 구현.
- `lib/goOfficial.js`: 공식 카드 전용 Storage `go-official-cards`, 전용 기능 플래그.
- 기존 카메라 `go_cards`와 공식 카드 소유 기록은 **코드상 분리되어 있다.** DB에 실제 테이블이 생성돼 있는지, 마이그레이션 적용 상태는 별도 검증 필요.

**최신 기획과 차이:** 기존 main은 공식 사진 슬롯 1~5 + 히든 슬롯 6 (5+1), 최신 Figma는 일반 슬롯 1~4 + 히든 5 (4+1). 기존 소스의 무료 뽑기·히든 지급 로직도 구 규칙이라 그대로 배포할 수 없다. 사용자 데이터 이전·기존 소유 기록의 슬롯 매핑을 결정하기 전에는 스키마/운영 데이터를 수정하지 않는다.

`lib/goStage2Collection.js`는 현재 DB와 무관한 미연결 보조 계산 코드로, 실제 공식 보유 시스템을 대체하거나 신규 데이터 모델이 필요한 증거가 아니다. 중복 구현하지 말고 기존 main 코드를 분기 작업에 필요한 범위만 선별적으로 통합/수정한다. 진행 전 기존 main의 SQL/RPC, 관리자, 공식 UI 전부 분석할 것.

- 실테이블 확인: `go_official_sets`, `versions`, `assets`, `owned`, `hidden`, `daily_draws`, `purchases`, `issuance_markers` 모두 존재·RLS ON. 모두 0행. 대조 `go_cards` 55행. 설치는 검증, 공식 카드 실 발급·구매 성공은 **검증 불가(데이터 없음)**.
- Storage `go-cards` (비공개·3 MiB), `go-official-cards` (비공개·5 MiB) 모두 존재.
- 함수 `go_official_draw`, `manage`, `mark_seen`, `new_draft`, `purchase`, `record_issuance`, `resolve_duplicate` 존재. 실제 호출·트랜잭션 검증은 하지 않음.
- **실제 스키마가 기존 5+1 전제임이 검증됨**: `go_official_assets.slot` 체크 1..6, `go_official_owned.slot` 체크 1..5, `go_official_hidden`은 (member_id,dog_id) PK로 별도 관리. 따라서 최신 일반 4종+히든 1종 정책과 코드/DB 모두 불일치. 공식 데이터 0행이므로 데이터 이전 위험은 낮아 보이나, 기존 설치된 DB가 자동으로 4+1로 변경된 것은 절대 아님.
- 운영 URL의 익명 `/api/go/official` 조회는 외부 검색 도구에서 접근 실패하여 실제 HTTP 응답 코드와 환경변수 플래그 상태는 확인되지 않음. 운영 기능 노출을 단정 금지.
- 다음 차수 내 작업: 기존 main 공식 시스템을 재사용하여 **안전한 신규 마이그레이션 초안** 및 최신 4+1 정책에 맞는 서버 함수/코드 변경, 독립 테스트 환경에서 실제 발급 시나리오 검증. 사용자 최종 배포 승인 전 운영 DB에 변경을 적용하지 말 것.

## 코드에서 확인한 현재 데이터 경계
- 기존 `go_cards` 및 `go_card_index`는 촬영한 나만의 카드와 공개 게시물의 목록/삭제에 사용됨.
- `lib/server/goCollection.js`의 `go_album_photo_counts` 기반 `counts`는 사진 수집 기준이며 신규 공식 카드 보유수까지 합산한다고 가정하면 안 됨.
- `components/GoDogAlbum.js`의 `total`은 현재 `/api/go/cards?mine=1&dog=...`에서 받아서 나만의 카드 수량. 공식 카드 구현 전 이 값을 총 보유수로 표시하는 기존 화면은 신설 공식 카드와 통합될 때 조정해야 함.
- 기존 main에 관리자/공식 카드 보유·중복/히든 서버 코드가 일부 구현되어 있음. 그러나 최신 4+1 정책으로의 정합성과 운영 DB 적용 여부는 미검증. **서버 보장 없는 클라이언트의 히든 지급을 구현하지 말 것.**
- 카드 마지막 삭제 시 해당 강아지의 도감·배틀 전적 삭제 정책은 향후 공식 카드와 커스텀 카드의 통합 상태를 기준으로 서버에서 구현/검증해야 함. 현재 코드로 정책 충족을 주장하지 않음.

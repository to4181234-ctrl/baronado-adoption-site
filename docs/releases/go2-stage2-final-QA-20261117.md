## 구현한 2차 범위
- 기존 `main` 공식 카드 보유·세트·히든·관리 API를 신규 설계 없이 재사용. 일반 슬롯 NO.1~4, HIDDEN 슬롯 NO.5에 맞춰 경계·이미지 포맷 수정.
- 기존 `go_cards`(나만의 카드)와 `go_official_owned`/`go_official_hidden`(공식 소유권) 저장 경계 유지.
- 강아지별 도감에서 공식 멍카드/나만의 카드 전환(원본 Figma의 하단 메뉴), 종류별 보유 개수, 상단 공식+나만의 합산 수량. 내 도감 홈에서도 두 종류 보유를 수집 상태에 포함.
- 원본 카드 프레임과 별 이미지 재사용: 미보유 일반 카드 물음표, 히든 잠금 및 NO.5, 보유 카드, NEW 표시. 보유 4종→HIDDEN 직접 클릭→서버 확인→기존 `GoCompletion` 카드 등장 연출, 반복 요청 시 추가 지급 없음.
- 나만의 카드: 페이지 간 다중 선택, 50장 제한, 마지막 선택 해제 시 모드 종료, 0장 상태로 선택 시작 허용, 취소 시 선택 보존, 삭제 실패 시 같은 모달에서 오류/선택 보존, 성공 뒤 카드 목록 갱신, 정렬 시 첫 페이지로 이동.
- Figma 삭제 팝업 331×210px, 노란 취소/삭제 버튼 각 115×33px, MonaS12.
- `docs/sql/stage2-four-plus-one-DRAFT.sql`: 서버 RPC·DB 체크 제약·기존 전적 보호·마이그레이션 가드. **운영 미적용**. 3차/4차 코인 가격·상점·공식 카드 관리자 최종 UI는 후속 단계 범위이며 이때 통합 회귀 테스트 필수.

운영 Supabase에 쓰기 없음. 별도로 격리한 PostgreSQL에 운영 테이블의 필요한 칼럼/제약/함수를 재현하고 미배포 4+1 SQL을 실제 실행. 최초 SQL 함수 종결자 누락을 발견하여 수정 후 트랜잭션 적용 PASS.

- 이미 해금한 회원의 재요청은 `new=false`, 히든 중복 기록 없음.
- 다른 회원·존재하지 않는 회원의 요청 거부.
- 일반 소유 슬롯5 및 관리자 에셋 슬롯6에 대한 DB CHECK 차단.
- 관리자 4장만 등록 시 발행 거부, 일반4+히든1 모두 등록 시 발행 성공.
- 랜덤 뽑기와 지정 강아지 구매 시 히든 자동발급 없음.
- 구매 재요청에 동일 `request_id`를 넣어도 중복 결제 없음.
- 마지막 나만의 카드 삭제 시 같은 강아지 공식 카드가 남아 있으면 기존 배틀·교감 기록을 보존.

- 유의: 위 결과는 **실제 운영 Supabase 데이터에서 발급을 실행한 테스트가 아니며**, 해당 프로젝트에는 기존 확인 시 공식 데이터0건·나만의 카드55건. 최종 운영 배포 승인 후 적용 순서를 반드시 관리.

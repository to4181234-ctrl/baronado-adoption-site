## A. 최종 확정 기능 요구사항

1. **무료 뽑기**: 한국시간 1일 2회, 매일 자정 초기화. 내 도감에 `랜덤 멍카드 뽑기 >` / `1일 2회 한정 무료` 독립 항목 추가. 퀘스트에서는 제거하고 `quest_draw` 신규 10C 보상 지급 중단. 돌보기 10C, 방문 인증 30C, 배틀 최초 10C는 유지.
2. **스토어 디자인**: Figma 정확히 적용. 2열, 카드 166×265, 랜덤은 노란 물음표 / 지정 랜덤은 연두 강아지 실루엣. 제목 `랜덤 카드 뽑기` / `지정 랜덤 카드 뽑기`. 설명 문구 Figma 그대로, 가격 폰트 **11px Bold** 그대로. 상점·말랑이 원본 유지.
3. **목줄 선택**: 선택한 목줄 이미지 **약 10% 확대**만 적용. 색 배경·테두리는 금지. 최소 44×44px 터치 영역. 무료/스토어 공통.
4. **뽑기 애니메이션**: 연출 단계 수 유지. 목줄 pop·반짝임 1.30초 → **0.70초**, 카드 공개 자동 전환 1.65초 → **0.95초**. 유료 결제 확인 과정 유지. 모션 감소 사용자 설정 존중.
5. **전체 수집 이후 뽑기**: 모든 일반 카드 보유자도 무료/60C/100C 뽑기 가능. 지정한 강아지의 4종을 전부 모아도 해당 강아지 지정 뽑기 가능. HIDDEN은 일반 뽑기에서 제외.
6. **중복 능력치 비교**: 무료/유료 공통, 기존 카드 유지 또는 새 능력치로 교체. 사용자가 비교창 X를 클릭하면 **기존 능력치 유지로 서버 확정**(추가 확인 없음). 오류/연결 끊김은 자발적 X 닫기와 구별하고 복구 경로 확보.
7. **멍배틀 화면 떨림**: 카드 대결 충돌 애니메이션 진행 중 **화면 전체가 움찔거리는 증상**, 랜덤/친구 1:1 재현 진단; 기존 타격 연출은 보존하고 레이아웃/viewport 이동 제거.
8. **1:1 READY UI**: `준비 완료 · 상대와 동시 공개` 버튼을 방 제목/나가기 버튼 바로 아래, 나·친구 정보 상단으로 이동. 준비 상태 네모칸은 **READY가 서버에서 확정된 경우만 노란색**. 카드 선택만으로 상태 문구나 박스색 변화 없음. 준비 취소 시 기본색 복귀.
9. **카드 선택 강조 통일**: 내 도감과 실시간 1:1 모두 선택 카드 **노란 배경**, 바깥쪽 **황금색 사각 테두리 제거**, 카드 본체 검정 픽셀 테두리 유지.
10. **가격**: 랜덤 **60C**, 지정 랜덤 **100C**. DB 결제 금액/검증/영수증/재시도/프론트 동시 반영. 과거 200C/300C 기록은 보존.
11. **확률**: 무료·유료 랜덤·유료 지정 공통 **보유(중복) 60% / 미보유 40%**. 두 풀 중 하나가 없으면 나머지 풀 100%. 지정 뽑기는 선택 강아지의 일반 카드 1~4종 내에서 적용.
12. **멍배틀 보상 추가 변경**: 하루 첫 완료 배틀 랜덤·1:1 공통 **승/패/무 +10C만**, 이후 두 번째부터 **승리자에게만 +3C**, 일일 승리 횟수 무제한, 패/무 0C. 첫 배틀 승리에는 +3C 중복 금지. 정상 완료된 리매치 포함. 취소/미완료 0C. 두 유형에 공통 '당일 첫 10C'를 원자적으로 적용.
13. **상대 선택 화면**: `누구와 멍배틀할까요?`에서 상대 멍카드 보유 갯수 표기만 제거. 다른 선택 기능 유지.

## B. 실제 운영 DB에서 확인한 차단 요소 — 구현 전 반드시 마이그레이션 설계

아래는 2026-11-19 읽기 전용 스키마 조회와 `pg_get_functiondef` 기반이며, 현재 운영에는 어떤 SQL 변경도 적용하지 않았음.

- `go_official_daily_draws`: PK `(member_id, local_day)`. **1일 2회 구조와 충돌**. `go_official_draw`도 하루 1행 검색 후 그대로 재생하는 구현. draw ID/순번 및 기존 일일 기록 호환 마이그레이션 필요.
- `go_official_draw`: 현재 두 카드 풀이 모두 존재할 때 `random()>=0.6` → 보유 40% / 미보유 60%, 요구사항과 반대. 성공 시 `quest_draw` +10C 지급. 둘 다 변경.
- `go_official_purchases`의 `go_official_purchases_coins_check`: `coins IN (200,300)` 제약. 60/100 추가하되 **기존 200/300 구매 이력**의 유효성 유지 필수.
- `go_store_purchase`: 가격 `random=200`/`specific=300`; *미보유* 일반 카드만 SELECT하고 즉시 `go_official_owned`로 INSERT. **중복 비교·수집 완료 이후 구매 불가**. 거래 단위의 중복 후보 능력치, 보류/확정 상태 및 idempotency 키 설계 필요.
- `go_official_resolve_duplicate`: 현재 **당일 무료 뽑기의 1행**만 기준으로 `p_replace` 수행. 무료 2회/유료 거래별 독립 식별과 날짜 경계·오류 복구 처리가 필요. X 닫기 시 유지 확정은 동일 서버 경로 사용.
- `go_coin_transactions_event_type_check`: 허용 이벤트 `care, quest_care, quest_visit, visit_reversal, store_purchase, quest_draw, quest_battle, admin_grant`. 무제한 승리 +3C 신규 이벤트를 추가해야 함. `UNIQUE(member_id,source_key)` 활용으로 배틀·라운드별 1회 지급 보장.
- `go_battle_reward_random`: 현재 첫 `quest_battle` +10C만 발생; 이후 0C. 랜덤 배틀의 승리 식별과 원자적 지급 설계 필요.
- `go_pvp_action`: 실시간 양측 준비 완료 시 두 플레이어에게 각각 하루 첫 `quest_battle` +10C; 이후 0C. 원자적 라운드별 승리 +3C 추가 및 재요청 방지 필요.
- 유효 강아지: 기존 운영 기준 `adoption`, `NOT adopted`, `go_dog_release_ready`, 일반 slot 1..4만 유지. HIDDEN 해금 경로는 변경하지 말 것.
